# ぱかっ！ママとおなじおべんとうづくり（gf-261121-nx3）

## 起動方法
- `index.html` をそのまま開く（file:// でも Pages のサブフォルダでも動く。CDN なし）。
  同じフォルダの `later.js`（歩く・公園）と `assets/fallback.jpg`（WebGL が無いときだけ）も一緒に置くこと。
- 作り直すときだけ: `npm install && node build.mjs`（`index.html` 約 0.68MB ＋ `later.js` 約 60KB を作る。実行時ビルドは不要）。

## お話
朝の台所で炊飯器を「ぱかっ」→ ごはん・ふりかけ・おかず5つをママとおなじに詰めて、ふたを閉めてバッグへ →
公園まで歩く（バッグを揺らせる）→ レジャーシートでふたを「ぱかっ！」、朝つめたとおり（置き場所・ふりかけの絵・揺らした分の片寄り）に出てくる →
今度はママの菜箸がまねをして同じ物を食べる → バッグからデザートのいちご → 次の朝へ（ママのふりかけの形が変わる）。

## 確認したこと（390×844 で1回通し）
- 読み込み・開始時にコンソールエラーなし。
- 台所 → 歩く → 公園 → デザート → おしまい → 次の朝（2日目）まで通して遊べた。
- 各段階で「光る物1つ＋うっすら光る行き先」が画面内に出ていること。放置で 揺れ → 菜箸のこんこん → 半透明の指のお手本 の順に強まること。
- テクスチャはすべて canvas の手続き生成、音は Web Audio 合成（外部素材・外部 AI は不使用）。

## 既知の問題
- 実機（iPhone / iPad）では未確認。音も耳では未確認（合成音の音量・音色は実機で要調整の可能性）。
- 通し確認は遅い headless 環境のため「描画を間引いてゲーム内時間を実時間で進める確認用ラッパー」で行った。製品の `index.html` そのものは起動とエラーなしの確認のみ。
- 台所に入ってすぐ（裏の下ごしらえが終わる前）に歩く場面へ進むと、従来どおり白いフェードの裏で生成するので 1 秒前後かかることがある。
- 裏の下ごしらえ（芝のテクスチャ・歩く場面の組み立て）は1回が重めの仕事なので、遅い端末では指を離している間に一瞬カクッとする可能性がある（実機未確認）。
- 横画面は操作できるが、縦優先の構図のため物が小さめ。
- 台所のバッグの段階で、天板の手前の縁と下の扉（無地）が画面の隅に映る。
- ごはんの上に置いたおかずは、ふたを閉めている間は隠している（ふたを突き抜けて見えないため）。
- 保存は場面の切り替わり時のみ。台所の途中で再読込すると台所の最初から。

## 描画パフォーマンス（iPhone / iPad 向け）
- 描画ピクセル数の上限 約 250 万（`engine.js` の `PIXEL_BUDGET`）。iPhone は DPR 2 のまま、大きい iPad だけ内部解像度を少し下げる（MSAA はそのまま）。
- 動的解像度は 60fps 目標: 遅いと 0.85 倍ずつ下げ、速いと 1.12 倍ずつ戻す。下げても速くならない（省電力モードの 30fps 固定など）ときは元に戻して下げるのをやめる。
- 影マップは「影を落とす物・ライトが動いたフレームだけ」描き直す（台所で静止中は影の描画を省く）。頂点シェーダで揺れる草は `userData.shadowAnimated = true` で毎フレーム描き直す。
- 真っ白のフェード中は描画を省き、フェードが透明のときは要素を隠して WebGL の上に余計な合成レイヤーを作らない。
- 見た目（マテリアル・影の種類・テクスチャ）と遊びは変えていない。実機での fps は未計測。

## 起動の速さ（初回起動を軽く）
- 最初に読むのは `index.html`（three.js・台所・共通部分）だけ。歩く・公園は `later.js` に分け、台所が見えてから
  `<script>` で裏で読み込む（`src/later_loader.js`。file:// でも動く。更新時に古いキャッシュを使わないよう `?v=中身のハッシュ`）。
  `later.js` は three.js や小物モジュールを自分では持たず、`index.html` 側が `window.__bentoShared` に出した同じ実体を使う
  （`src/shared.js`。three.js は later 側が使う名前だけを build.mjs が拾って公開する）。
- 台所で遊んでいる間、指が離れているフレームの合間に1つずつ: later.js の読み込み → 公園のテクスチャ・形
  （`props_park.js` の `parkWarmSteps`。once キャッシュされる決定的な生成なので見た目は同じ）→ 歩く場面の組み立て
  → そのシェーダのコンパイル → 公園も同様（`src/idle.js`）。長くかかったフレームは動的解像度の計測から外す（`engine.skipPerf`）。
  → 台所 → 歩くの切り替えで白いまま待つ時間が短くなる（headless の計測で 約2.7秒 → 約0.9秒）。
- 開いた瞬間から白い画面（`#fade` の初期値を不透明に）。以前は暗い茶色 → 白 → 台所と色が2回変わっていた。
- 代替画像（WebGL が無いとき）は `index.html` に埋め込まず、そのときだけ `assets/fallback.jpg` を読む（約 52KB 軽く）。
- 手続きテクスチャの生成を速く（結果の画素は同じ）: ノーマルマップ作成時に高さ canvas を GPU から読み戻さず、
  手元の画素をそのまま使う／2 のべき乗周期のノイズは剰余をビットマスクで求める（1,600,000 点で旧実装と完全一致を確認）。
- 見た目（テクスチャ・マテリアル・構図）と遊びは変えていない。台所・歩く・公園の画面を旧版と見比べて同じことを確認（揺れ・光るヒントの時刻差のみ）。
