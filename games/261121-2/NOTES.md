# じょうろで！ベランダのミニトマト（gf-261121-nx2）

## 起動方法
- `index.html` をそのまま開く（file:// でも Pages のサブフォルダでも動く。約 0.93MB。WebGL が使えないときだけ `assets/fallback.jpg` を読む）。
- 最初からやり直す: URL の末尾に `?reset`。軽い設定を試す: `?low`。
- 作り直すとき: `node build.mjs`（`src/` の番号順の js と `src/shell.html` を結合して `index.html` を作る。実行時のビルドは不要）。

## お話
苗を鉢に植える → 蛇口でじょうろに水をくむ → 運んでシャワー → 夜が来て朝に育つ（苗 → 花 → 青い実 → 赤い実）→
収穫してざるへ → じょうろで洗う → ぱくっと食べる → 夕方に最後の1個が赤くなる → 星空とオルゴール → じょうろに触ると次の朝（周回）。

## 確認したこと（390×844、ヘッドレス Chromium）
- 読み込みと最初のタッチでコンソールエラーなし。
- 手がかりの対象（`G.Game.target()`）だけを頼りに、お話を最初から次の周回の朝まで1回通して遊べた（エラー 0）。
- 各段階で、次の1操作にきらめきが出ること、放置で光のたまり・半透明の指のお手本に強まることを画像で確認。
- `thumb.png` と WebGL 失敗時の代替静止画（`assets/fallback.jpg`。失敗したときだけ読み込む）は実際の画面から作成。

## 既知の問題・未確認
- 実機（iPhone / iPad）では未確認。音は合成で、耳では未確認（音量のピークのみ確認）。
- iPad での速さは未計測（動的解像度と、遅いときに影を切る仕組みは入っている）。

## 描画の軽量化（iPhone / iPad 向け）
- 動的解像度は 60fps を目安に上げ下げ。最初の描画画素数は約 1.6M 画素から（iPad は控えめに始め、速ければ 2 倍まで戻す）。
  下げても速くならないとき（低電力モードの 30fps 制限など）は元に戻して触らない。影を切るのは 30fps 前後以下のときだけ。
- 空のドームは不透明物の後に描き、隠れた画素の計算を省く。雲の細部・月の模様は見える画素だけで計算。昼は星を描かない。
- 起動時に全シェーダを先に作る（途中で初めて出る物でのカクつき防止）。環境マップは同じ描画先に描き直す。
- 変更前後で昼・夕・夜の画面を比べ、揺れている株のほかは同じ絵であることを確認。
- stage 2（青い実）の途中で再読み込みすると、花びらが散る動きがもう一度出る。
- スマホの縦画面では蛇口のハンドルが小さく見える（当たり判定は大きく、きらめき・しずく・指のお手本で示す）。
- 夜の場面はやや暗め（物は見える）。

## 初回起動の高速化（下書き → 裏で清書）
- 重い手続きテクスチャ（床・腰壁・鉢・土・水受け・バケツ・じょうろ・ざる・葉の法線・水面のさざ波）は generator で書き、
  起動時は 1/4 に間引いた下書きをその場で作って最初の場面をすぐ出す。本来の大きさの清書は `U.bg` に積み、
  幕が上がってから 1 フレーム 4ms ずつ作り、できたら同じテクスチャの絵を差し替える（材質はそのまま）。
  床の下書きだけは、細い目地と細かい粒が消えないよう間引き率に合わせて描き方を変えている。
- 起動時のシェーダは最初の描画で見えている物の分だけ。隠れている物（ざる・実・水・手がかり など）の分は、
  幕が上がってから 2 フレームに 1 つずつ先に作る（最後には以前と同じ 33 個がそろう）。
- 裏の作業中のフレームは動的解像度の判断に数えない（作業のせいで解像度を下げないため）。
- 計測（ヘッドレス Chromium、390×844）: 起動処理（boot）1.37 秒 → 0.39 秒。清書後の画面は変更前と同じ絵。
- 下書きの間（端末により数秒）は床などのきめがやや粗い。
